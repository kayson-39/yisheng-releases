# 译声 Windows 发布检查

这份清单给维护者。开发工作区、日常安装目录和 `artifacts` 都不是发行包，不要整目录压缩上传。它们可能含测试录音、日志、字幕历史或个人配置。

## 1. 核对来源并组装 stage

首选原 0.10.7 发布工程中的 `work/release-0.10.7/payload`。其中 `发行文件清单.json` 的 SHA-256 为 `70b6b6f72597f04e3a95acd2240ac7a276d89475cc7e8823a91d52e33a55ed55`。部分本机安装目录仍带 0.10.6 清单；它不是 0.10.7 的版本证据。两份已审核清单中允许继承的 8,681 个文件路径、摘要一致；这不是最终 stage 的文件数。

在工程根目录运行，示例中的路径需替换为真实路径：

```powershell
python tools/stage_release.py --base "D:\原发布工程\work\release-0.10.7\payload"
python tools/stage_release.py --base "D:\原发布工程\work\release-0.10.7\payload" --output "D:\构建\候选-001"
```

第一条只列计划；第二条才复制文件并核对摘要。输出父目录必须存在，目标目录必须是新目录。旧运行库、引擎、模型和启动器先过固定清单及路径白名单，再叠加当前工程中明确列出的程序、使用说明和许可说明。日志、录音、用户配置、旧卸载器、未知模型及构建机安装来源不进入 stage。增加依赖或模型时，应单独审查来源和许可，不要改用递归通配符。

## 2. 构建单文件安装器

使用原工程的完整 `work/tools/inno7`，而不是网上单独找到的 ISCC.exe。已核验原 Inno Setup 7.1.1 编译器签名有效（Pyrsys B.V.）；本机 ISCC.exe SHA-256 为 `e0f9f1dc32032650c6629f6dee41eb6d20ba140e4e3c07c25d8a24f9ba781644`。这**不是**译声安装器的代码签名。编译步骤、输出限制及隔离解包方式见 [Windows 安装器构建说明](installer.md)。

单 EXE 不嵌入约 4.25 GB 的 Sakura 翻译权重。安装时可选择复用匹配摘要的本地同名文件、从指定版本下载并核验，或跳过。现有同名文件摘要不匹配时，不应静默覆盖。离线全新电脑若没有权重，不能宣传为“安装后即可离线使用 Sakura”。

## 3. 公开发布前的放行条件

代码回归、白名单校验、编译成功和隔离解包分别证明不同的事。`/VALIDATE=1` 不注册卸载项、不建快捷方式、不启动应用、不下载模型，不等于普通用户完成安装。下列事项未有独立证据时，候选包只能用于测试：

- 在独立 Windows 10/11 x64 普通用户虚拟机上正常安装、首次打开、选择设备并实际识别翻译；覆盖断网、缺模型、下载失败及恢复。记录系统、GPU、版本、结果。
- 从真正的 0.10.7 安装包升级，核对升级前后历史、配置和自有模型；检查运行中升级、拒绝降级、卸载与重装。用专用测试账户和哨兵数据，不对日用安装做卸载演练。
- 核实项目代码、背景图、字体、识别模型、翻译模型、运行库及编译器的分发条件；逐项补齐归属与必要许可文本。商业发行还需确认编译器的商用授权。哈希正确或有 NOTICE 不等于获得再分发授权。
- 使用合法发布者证书签署**最终**安装器，验签后再记录大小、SHA-256 和测试范围；只分发该产物，不附带历史日志或原构建目录。
